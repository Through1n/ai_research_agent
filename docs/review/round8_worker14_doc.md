## 3. T2：AI 协同说明写了什么（第 9 章）

### 3.1 9.1 AI 参与了哪些工作

5 行表格：模块并行施工（六个模块按独占文件边界分给多个 AI Worker）/ 缺陷定位与修复 / 审查与放水核查 / 文档与报告撰写 / 实跑取证，每行均写明"AI 怎么做的"与"人负责什么"。结尾列出 **AI 明确不做的三件事**（不越权改文件、不编造数字、不擅改第三方依赖与锁定版本），并给出本轮实例（三位修复工程师都列出"我发现但无权更改"的位置）。

### 3.2 9.2 人工主导的架构决策与验证（4 条）

1. **「LLM 只写正文 + 系统确定性拼接 References」**——抗幻觉总架构决策：真实文献字段本就在白名单里，拼一遍即可；把卖点从"prompt 约束住模型"升级为"模型没有机会碰这块内容"，同时 139.3s → 44.6s。
2. **用真实 API 端到端实测取代离线推断**——主动选择承担"暴露 6 个缺陷 + 被外部审计打 5.5/10"的代价。
3. **接受放水核查结论并重写验收断言**——逐条列出 4 类收紧（硬编码 True → `chunks > 0`；`n_fw >= 0` → 条数 >0 且状态合法；只验长度 → 验结构/占位符/真实条目；QA 命中一半 → 全命中），用例 19 → 21，收紧后仍全绿。
4. **数据纪律优先于功能完整**——`None` + `error_kind`、`title_attribution_unconfirmed` 不计分、"0"不能当作"被引 0 次"。

### 3.3 9.3 Prompt 调优策略（赛题要求的重点，三条真经验）

| 经验 | 写进文档的内容 |
|---|---|
| ① **能确定性生成的东西就别放进 prompt** | 现象（模型用一行元指令替代整章）→ 三步进退（加措辞无效 → Strict 版仍可能再犯 → 认清是架构问题）→ 改为确定性拼接；并说明同一做法已复用到图谱确定性综述 |
| ② **抗幻觉关键在生成后可执行的 Detection** | 占位废稿被判 `ok=True` 的完整失败链条（0 条 → 相似度循环一次没进 → `hallucinated` 为空 → 通过）；根因是"缺 Detection 而非阈值松"，修复只收紧不放宽（阈值仍 0.8）；反向验证说明新判定对"无章节""编造条目"判 FAIL 而旧版判 PASS |
| ③ **相似 ≠ 同一：0.88 相似度会骗人** | 词袋 0.88 高于 0.85 阈值导致 55 次被张冠李戴；Round 7 数据层补 `_token_order_same` 词序校验 + `title_attribution_unconfirmed`，Round 8 才发现平行出口 `detect_frontier` 没读标注 → 统一闸门；三条通用结论（阈值救不了你 / 数据层诚实 ≠ 系统层诚实，需全仓排查消费者 / 系统要保留"自我怀疑"的表达能力） |
