1 项目概述

2026 年，大语言模型（LLM）与 AI Agent 技术引发了全球科学研究范式的深度变革，AI4S（AI for Science） 已从简单的文献摘要提取，跨越到能够自主进行文献阅读、逻辑推理、假设提出、实验代码生成乃至论文草稿撰写的 「AI 科学家助手」新阶段。然而，真实科研场景对学术规范、长上下文、复杂排版与「幻觉零容忍」的确定性要求， 使通用 Chatbot 远无法满足需求。

本项目面向真实科研全流程，从 0 到 1 设计并实现一款全栈式、具备自主规划与协同能力的 科研助手 Agent。系统以现代 Web 应用为形态，后端 Agent 通过任务规划、多专家路由与函数调用闭环， 自主调度文档解析、混合检索、学术 API、图谱计算与代码执行等 16 个工具，覆盖赛题要求的六大功能模块， 实现「文献导入 → 解析 → 问答 → 阅读翻译 → 检索追踪推荐 → 图谱综述 → 写作输出」的完整闭环。

设计目标：高可靠（抗幻觉、可溯源、执行护栏）、自主化（Agent 规划与工具闭环）、 全流程（六大模块贯通）、可验证（官方 PDF 数据集实测通过）、可复现（容器化、一键部署）。

3.2 Agent 运行数据流

① 输入自然语言意图
② 防护注入/密钥校验
③ 规划动态拆解步骤
④ 路由6 类专家分流
⑤ 闭环函数调用执行
⑥ 溯源内联引用生成

Agent 内核采用「LLM 优先、规则兜底」策略：路由与规划优先由 LLM 以 JSON 输出，失败时退化为关键词路由与 固定步骤模板；工具执行采用原生 Function Calling + ReAct 文本解析双保险，最大迭代 8 轮， 超限则在无新增工具时强制总结，保证闭环可终止。每步记录 Trace（工具名、参数、结果摘要），前端可视化呈现「AI 思考过程」。

3.3 模块解耦

系统按 core / services / tools / ui / config 分包：core 仅负责推理与编排（agent / router / planner / memory / guardrails / llm / sandbox），services 封装业务能力（parsing / rag / library / graph / track / translate / writing / state），tools 将 Python 函数统一注册为 OpenAI Function Schema，ui 仅负责渲染。依赖单向向下， 便于测试与扩展；全部离线逻辑可在无 API Key 环境下自测运行。

4 AI 技术方案

4.1 模型选型与理由

类型选型选型理由

4.2 跨语言混合检索（Dense + Sparse + RRF + 重排）

学术场景的典型矛盾是：文献是英文、提问是中文，单一向量检索对「超参数、GPU 型号、BLEU 分数」这类 精确词面反而不如关键词检索。系统为此构建了四段式检索管线：

查询 → ① 查询扩展（LLM 在线生成英文检索词，离线术语映射表兜底）
     → ② 双路召回：Dense（Chroma 向量 top-k）‖ Sparse（BM25Plus × 多扩展查询取最大）
     → ③ RRF 融合：RRF(d) = Σ 1/(60 + rank_i(d))
     → ④ 可选 LLM 重排 → 注入带【n】编号的编号化上下文

分词设计是稀疏路生效的关键：文档与查询统一经「英文 Porter 词干归一 + 中文二元组切分」， 并将 BM25 的 IDF 下界设为 0.05（标准 BM25 对「全部文档都含查询词」的小语料库会把 IDF 压成 0，导致中文查询零召回—— 本系统实测修复后同查询 BM25 召回 7 条 / Dense 召回 11 条，融合后重排精确定位）。扩展词与两路召回数量在 问答页「检索调试」面板透明展示，检索行为可审计。

4.3 抗幻觉生成与源头溯源

  • 生成仅以编号资料为事实来源，系统提示强制 【n】 内联角标、资料不足必须明说、禁止编造；
  • 生成后校验角标范围，越界自动触发一次修复重写（validate_citations）；
  • 每条资料附论文 ID + 页码锚点，前端点击即展开对应原文片段（Source Tracing）；
  • 写作框架的 References 只允许引用本地真实文献，缺失显式占位，杜绝幻觉引用。

4.4 内容级语义去重（不依赖文件名）

去重采用「整篇向量 + 正文分段指纹」双通道：入库时均匀抽取 5 个 1200 字内容段生成指纹向量， 查重时与库内论文指纹逐段交叉匹配、按来源聚合取平均相似度；同时保留整篇向量相似度作为第二信号， 两通道分别给出可解释证据（「分段指纹内容匹配 98%」或「整篇语义相似度 100%」）。 判定规则：通用阈值 0.90；同一 arXiv 号且相似度 ≥ 0.7 判为版本演进（仍以语义为依据，非仅凭文件名）， 并触发「保留最新版」建议与版本差异总结。

官方用例实测：先传 v7 再传 v1 → 命中 98%（最佳段 100%，附 arXiv 同号证据）； 把 v1 改名为 attention_v1.pdf 再传 → 仍 100% 命中，证明判定完全基于内容。

4.5 多智能体路由与规划

Router 将意图分流至 6 类专家（问答 / 检索 / 图谱 / 写作 / 阅读 / 解析），各专家仅持有完成任务所需的 工具子集，降低误调用面；Planner 将复杂任务动态拆解为有序步骤并交由 Function Calling 闭环执行。

5 核心功能实现

5.1 模块一：PDF 管理与细粒度解析

  • 语义去重：见 4.4，附证据链与「覆盖 / 保留 / 取消」三分支交互、v1 vs v7 版本差异自动总结；
  • 细粒度解析：结构化抽取标题、作者机构、摘要、三级标题树、表格、图表、LaTeX 公式、参考文献与附录； 扫描件页自动走多模态 OCR 通道；
  • 长文档工程：逐页解析 + 分页分块 + 进度条反馈，541 页正版教材实测 1523 分块 / 26.3s / 292MB。

5.2 模块二：抗幻觉问答与多文推理

单篇问答可定位超参数、GPU 型号数量、BLEU 分数、完整引用等细粒度信息并给原文锚点；多篇推理通过跨文档 Chunk 聚合，支持 BERT 与 Transformer 的承袭 / 抛弃、GPT-1/2/3 参数量演化、LayerNorm 位置与上下文窗口 递增等对比分析，答案内联 【n】。检索调试面板显示 Dense / Sparse 两路各自召回数与查询扩展词。

5.3 模块三：版式阅读与双向联动翻译

  • 坐标级原生还原单 / 双栏版面（文字可选中），提取标题树导航；
  • 引用双向跳转：以 References / Bibliography 标题锚点定位参考文献区（兼容正文末尾与独立页起始等 IEEE / Springer 排版变体），输入或点击正文 [11] 即返回规范化编号与完整条目原文，官方 v1 实测覆盖 [1]–[38] 区间 41 条；
  • 中英对比采用 JS 按比例 + 段落对齐双机制实现同步滚动与悬停联动高亮，代码与公式保留英文； 划词 / 悬停翻译经后端代理调用模型，前端页面不含任何密钥；支持整篇翻译与中译英学术输出。

5.4 模块四：检索、动态追踪与个性化推荐

  • 给定标题 / 参考文献列表，经 arXiv / PubMed / 搜索引擎自动抓取并入库，支持批量下钻； 引用含金量正则筛选自动剔除应付式引用；GitHub 开源代码链接自动识别并在推荐中加权；
  • 订阅式动态追踪：用户按话题订阅，系统持久化 last-seen 检查点，每次「检查新论文」只返回上次以来 新增条目并推送提示；另提供 scripts/watch_daemon.py 常驻守护脚本实现真·定期抓取， 与 Streamlit 会话解耦；
  • 多用户个性化推荐：推荐排序融合「点赞/踩反馈 + 用户画像领域匹配 + 开源代码可得性 + arXiv 分类命中」 四因子，逐条生成推荐理由；多用户 ID 隔离反馈账本（JSON 持久化），切换用户可见不同排序。

5.5 模块五：引用图谱与学术综述

引用关系判定三层递进：① 标题锚点定位每篇的参考文献区并切分条目；② 标题 token 倒排索引 + IDF 稀有度加权生成候选（词面巧合的泛词如 transformer 得 0 分，稀有词组合才计分）， 将 O(n²) 全文比对降为稀疏候选比对；③ 候选内以「条目↔标题」双向包含判定，另以复用库内向量的语义兜底 捕获缩写标题（如 BERT 论文标题被 Attention 论文引用）。

在「逻辑著作」层建图（同一 arXiv 号取最新版本为唯一节点，旧版本不产生孤立节点），运用 PageRank、入度、 中介与特征向量中心性挖掘基石 / 边缘论文；基于图谱自动生成领域综述；提取各文 Future Work，按时间线比对 后续论文摘要，自动标注并排除已被解决的旧 idea，提炼真正开放的方向。官方 PDF 实测：BERT → Attention 真实引用边， 证据为参考文献条目 100% 匹配，基石论文正确识别为《Attention Is All You Need》。

5.6 模块六：写作与可视化 Copilot

  • 依据 Idea 生成含 Abstract / Introduction / Related Work 的框架，References 仅引用本地真实文献；
  • 生成 Mermaid / TikZ / Graphviz / Matplotlib 架构拓扑图脚本，可经沙箱护栏后直接执行出图；
  • 读取 CSV 自动生成折线 / 柱状 / 散点 / 三维雷达 / 热力 / 平行坐标图，并提炼符合学术规范、说明核心趋势的 Figure Caption；
  • 中文摘要 / 全文一键精准翻译为学术英文。

7 技术创新点

7.1 技术创新

  1. 真 Agent 架构而非按钮脚本：Guardrails → 规划 → 6 专家路由 → Function Calling 闭环 → Trace 全程可视化，LLM 优先 + 规则兜底双保险；
  2. 跨语言混合检索：查询扩展弥合中英词表鸿沟，BM25Plus + 向量双路召回、RRF 融合、LLM 重排，检索过程可审计（调试面板展示两路召回与扩展词）；
  3. 内容级去重实证化：分段指纹交叉匹配 + 整篇向量双通道，各附可解释证据；改名场景 100% 命中，从机制上满足「非仅凭文件名」；
  4. 三层引用判定 + IDF 加权候选：标题锚点参考文献区 → 倒排索引稀有度候选 → 向量复用兜底，兼顾 IEEE/Nature 排版泛化与 40 篇规模 25s 性能；
  5. 订阅式增量追踪 + 多用户反馈推荐：last-seen 检查点只推「上次以来新增」，点赞账本 + 画像 + 开源可得性四因子排序，逐条给推荐理由；
  6. 执行级 Guardrails：AST 白名单沙箱先于执行拦截 4 类绕过手法，密钥永不进前端；
  7. 双机制同步滚动阅读：JS 按比例 + 段落对齐双通道同步、悬停联动高亮、划词后端代理翻译。

7.2 应用创新

  1. 贯通科研全流程的单一 Agent 入口，自然语言意图驱动、零脚本操作；
  2. 复现导向推荐：优先带 GitHub 开源代码的论文，回应「创意落地与实践复现」痛点；
  3. 无幻觉写作：框架 References 只引用本地真实文献，显著提升学术产出可靠性；
  4. 离线可复现设计：无 Key 环境下解析 / 检索 / 图谱 / 推荐核心链路全部可演示，规避现场网络风险。

8 总结、局限与展望

本项目围绕真实科研痛点，完成了具备 Agent 内核、跨语言抗幻觉 RAG、内容级语义去重、多模态解析、 真实引用图谱挖掘、订阅式追踪与学术写作可视化能力的全栈科研助手；六大模块闭环贯通，全部关键指标以 官方赛题 PDF 数据集实测背书（去重 98%/100%、541 页 26.3s、n=40 建图 25s、真实引用边与基石识别）， 并以三层测试体系保证可复现与稳定。

8.1 当前局限（诚实声明）

  • 参考文献区定位依赖标题锚点 + 启发式兜底，对极少数无「References」标题的异形排版仍需人工指定；
  • 语义兜底匹配存在缩写标题的边界情形，置信阈值在 precision/recall 间取折中；
  • 多用户推荐画像基于领域计数，尚无协同过滤；个性化深度受个人赛数据规模限制；
  • OCR 依赖多模态 API，离线场景以原生文本层功能为准。

8.2 后续展望

① 接入更多开源 / 本地推理模型与专用 OCR 管线（PaddleOCR / Marker），进一步降低成本与网络依赖； ② 深化 Multi-Agent 协同与自我进化（基于点赞反馈自动优化工具策略与检索权重）； ③ 扩展真正的多用户协同与云端部署；④ 增强实验代码自动生成与结果复现，向端到端「AI 科学家」演进。
