1. 项目概述

1.1 背景与动机

大语言模型（LLM）的通用推理与生成能力已经成熟，但把通用聊天模型直接用于学术科研这一高门槛、强证据、重引用的场景，会遭遇三类结构性问题。

第一类是检索与引用幻觉。 通用模型对文献的记忆停留在预训练语料，让它"给这篇论文的出处"时，页码、年份、甚至整条参考文献都可能被编造；更隐蔽的是"半编造"——真实标题配上错误的被引数、张冠李戴的期刊。在科研场景中，一条错误引用的代价远高于一句错误观点，因为它会沿着引用链继续传播。

第二类是版面感知缺失。 学术 PDF 中超过半数是双栏排版， naive 的文本提取按 PDF 内部对象流输出，左右栏内容会交叉串读；图表与其图注分离、标题树缺失、扫描件无文本层，都让 RAG 的上下文在进入向量库之前就已经语义断裂。上下文坏了，后面的检索与生成做得再好也是"垃圾进、垃圾出"。

第三类是科研流程割裂。 读文献用 PDF 阅读器、管文献用 Zotero、查新用 arXiv 网页、问答丢给 ChatGPT、画图用 draw.io、写框架再回 Word——工具间的每一次手动搬运都是一次上下文丢失。研究员真正需要的不是六个更强的工具，而是一个能理解意图、自主调用工具、且处处可溯源的统一入口。

本项目从 0 到 1 构建了这样一个意图驱动的科研助手 Agent：以自研 Agent 内核统一编排六大科研模块，把「文献解析 → 抗幻觉问答 → 版式阅读 → 检索追踪 → 引用图谱 → 学术写作」串成一条闭环，并且把"抗幻觉"作为贯穿全系统的第一设计原则——不是在答案后面加一句"以上内容可能不准确"，而是用拒答闸门、逐句引用校验、修复环、References 白名单四道工程化防线，让"不知道"可以被系统诚实地说出来。

1.2 目标用户与使用场景

  • 研究生 / 科研人员：需要快速读懂一批英文论文、跨文献对比方法与结果、追踪方向最新进展、起草开题或论文框架。系统的「跨文献问答」「图谱综述」「写作 Copilot」直接服务这一主线。
  • 教学与评审场景：经常没有真实 API Key 或外网受限。系统为此做了完整的离线降级——无 Key 时 PDF 原生解析、混合检索、语义去重、引用图谱、追踪增量比对等链路照常运行，演示数据一键加载（ui/sidebar.py 演示数据按钮 + ui/page_graph.py:57 _build_demo 演示图谱兜底）。
  • 工程复现场景：所有关键指标（长文档入库耗时、去重命中率、建图耗时）均可由 scripts/verify_official.py、scripts/bench_graph.py、scripts/selftest.py 一键复跑；单元测试 18 项（tests/test_core.py）。

1.4 与现有工具的本质差异

与通用对话产品（ChatGPT 类）相比：本系统的每一条结论都强制携带可点击的原文页码锚点，检索不到可靠依据时拒答而不是编造；写作模块生成的每一条 Reference 都来自上传 PDF 的 References 段真实抽取，越界角标会被白名单校验剔除。

与通用 RAG 框架相比：检索前有双栏感知的解析层保证上下文质量，检索后有逐句"覆盖率"引用校验（而非仅校验角标是否越界），生成后有修复环自动改写，评分侧接入了 OpenAlex/Semantic Scholar/Crossref 的真实被引数据且"取不到就明说"。

与文献管理工具（Zotero 及插件）相比： Zotero 强于"管"，本系统强于"懂"——内容级语义去重（改名的同一篇论文依然命中）、版本差异总结、引用图挖掘、综述与 Future Work 判定，都是 Zotero 生态不做的事。

故事 C：从检索到综述（演示路径 5+7）。 用户检索 arXiv 拿到 5 篇论文，一键下载入库；进入图谱页构建真实引用图（BERT→Attention Is All You Need 引用边被正确解析）；点"一键生成领域综述"得到四段式综述（研究脉络/主要方向/关键基石/分歧与展望），文末附 networkx 计算的图谱结构明细供核查；再点"Future Work 前沿扫描"，系统给出"已解决/存疑/开放"三态判定与引用图证据。断网时检索给出"可能原因 + 怎么办 + 用离线演示数据继续"的完整降级引导（演示路径 7b 实测）。

4.1 AI 模型选型理由

4.1.1 大语言模型（LLM）：统一 OpenAI 兼容协议，多厂商可运行时切换

项结论

项结论

项结论

4.3.2 检索优化：查询扩展 + 双路召回 + RRF 融合

  1. 查询扩展（services/query_expansion.py）：中文提问先由 LLM 扩出英文 / 同义词 / 缩写多个变体，LLM 不可用时退回内置词表，解决"中文问英文文献"的跨语言失配。
  2. Dense 路取各变体最大分（services/rag.py:182、:245，最多消费 MAX_VARIANT_DENSE = 4 个变体），缓解单一中文查询对英文 embedding 的低余弦。
  3. Sparse 路 BM25Plus 并行（SPARSE_K = 12）：锁定"超参数 / 型号 / BLEU 值"这类词面精确答案。
  4. RRF 无参融合（services/rag.py:97 rrf_fuse，常数 c=60）：不比较两路的分数量纲，直接融合排名，避免手工加权漂移。
  5. 可选 LLM 重排：失败时静默回退 RRF 结果，不影响可用性。
  6. 多篇对比防饿死：retrieve_per_paper 每篇保底 3 条 chunk，build_grouped_context 输出【Pn-m】分组角标。

4.3.4 版面判定优化：双栏误判 19.1% → 0%

实测：1111 页单栏语料误判率 19.1% → 0%，同时真双栏论文（BERT）正文页 10/10 仍被正确识别（没有用"永远判单栏"换取指标）。

4.6 抗幻觉机制（核心卖点，四道防线）

与 4.3.1 的关系：4.3.1 从"优化策略"角度列出四道防线的参数与实测效果，本节给出完整实现链路与失败路径。

防线一：拒答闸门（检索侧）

services/rag.py:410-413：top chunk 合成相关度（0.5×向量余弦各变体最大值 + 0.5×BM25 归一，rag.py:168 score_sources）低于 RELEVANCE_FLOOR=0.35（:16）时直接拒答、0 次 LLM 调用，回传 top3 候选片段供人工核对。

实测：无关问题（量子纠缠查询）top_score=0.1820 → 拒答，LLM 调用次数=0；相关问题 0.7422 → 放行。拒答文案为固定诚实话术："未在文献库中找到可靠依据，为避免幻觉我不作答。"（guardrails.py:31）

防线二：引用一致性逐句校验（生成侧）

core/guardrails.py：答案按句切分 → 每句归属其标注的【n】→ 与第 n 条来源 chunk 做锚点覆盖率比对（_overlap :51，刻意用覆盖率而非 Jaccard——来源 chunk 约 1200 字，Jaccard 会把正常引用稀释到 ~3% 误杀）→ 覆盖率低于 SUSPICION_THRESHOLD=0.15 的句子被标记"可疑引用【n】：重叠仅 x%"。同时校验角标越界（:127 validate_citations）与分组角标【Pn-m】存在性（:152 validate_grouped_citations）。

实测：编造句 "Training used 512 Google TPU v4 chips【1】" 被标记"重叠仅 10%"；真实句 "Training used eight NVIDIA P100 GPUs【1】" 覆盖率 84.5% 通过。诚实边界：纯中文句无英文/数字锚点时无法判定，系统不谎报"通过"（见第 8 章局限）。

防线三：修复环（自动改写，上限 1 次）

services/rag.py:418-429：校验失败时，把原答案 + 修正指令（"确保每条事实都带有效角标且角标指向的资料确实包含该事实；删除资料中没有依据的内容"）追加进对话，以 temperature=0.0 重生成一次，再校验；MAX_REPAIR=1 保证不死循环、可控成本（实测一次完整修复共 2 次 LLM 调用）。修复后仍有问题则以醒目 warning 逐条展示——宁可明示也不静默。

防线四：References 白名单（写作侧）

这是区别于"通用 RAG + 提示词约束"的实质性机制，链路如下（services/writing.py）：

  1. 白名单构建 reference_whitelist（:726）：优先从上传 PDF 的 References 段真实抽取（页级定位 References 标题 + 附录截断 _locate_reference_section :416，作者-年份流式切分 _split_author_year_flow :313，连字还原 _flow_text :208，噪声过滤 _is_noise :486），带质量自检 _quality_report（:546，未定位到标题/条目过少/缺字段比例过高 → low_confidence=True 直接判抽取失败）；失败则回退文献库 chunks 的 References 段，再回退库元数据，来源标签全程透出。
  2. 约束生成 generate_outline_verified（:956）：白名单注入 prompt，生成后先在原始输出上校验。
  3. 白名单校验 validate_reference_whitelist（:837）：抽出全部 [n] 角标（越界即违规）+ 按 References 标题切出条目段与白名单做标题实质匹配（归一化 + 包含/前缀快捷判定 + difflib 相似度，阈值 0.8）。
  4. 处置：违规角标替换为 [?]（_sanitize_citations :788），编造条目逐条列出并给出最接近白名单条目与相似度；UI 提供"🔁 重新生成（强化约束）"按钮一键 strict 重生成。

实测：BERT 论文 References 修复前只抽出 9 条（字段错位 + 附录 Question:/Answer: 噪声混入），修复后 56 条全对、0 噪声（1706.03762v1.pdf 另测抽得 36 条）；无 References 的 541 页书籍如实返回空列表，不再拿索引页凑数；毒样本测试中越界 [9] 与编造条目（相似度 0.14–0.36）全部被报出。

7. 创新点说明

按赛题要求，创新点分为技术创新点（7.1）与应用创新点（7.2）两类列出。第 4、5 条兼具技术与应用双重属性，这里按其落地形态归入应用创新点，其底层技术实现分别已在 7.1 所述的版面感知链路与工程韧性链路中交代。

7.1 技术创新点

  1. "四道防线"抗幻觉体系（核心创新）。通用 RAG 只做"检索 + 生成"，幻觉校验至多是提示词里的一句"请不要编造"。本系统把抗幻觉拆成四个工程化组件：检索侧拒答闸门（相关度不足 0 次 LLM 调用直接拒答）、生成侧逐句引用一致性校验（覆盖率口径逐句比对来源，能抓"角标存在但内容无据"的半幻觉）、闭环修复环（带原答案与修正指令的重生成，上限 1 次）、写作侧 References 白名单（从 PDF References 段真实抽取 + 质量自检 + 角标/条目双重校验）。四道防线全部有实测证据（评审沙箱复现），且失败路径全部"明示而不静默"。
  2. 版面感知先于检索（实现详见 4.3.4）。双栏判定不靠朴素中线二分，而是 4 条必要条件（横跨否决是关键——对全部块生效，含被剔除出候选集的宽块），把"上下文质量"问题拦在向量化之前；同一套栏判定同时服务文本入库（RAG chunks）与视觉渲染（阅读页），保证"看到的版面 = 检索到的上下文"。实测单栏语料 1111 页误判率 19.1% → 0%，同时真双栏论文识别能力保留（10/10 正文页正确）。
  3. 为演示鲁棒性做的系统工程（实现详见 4.2.1 / 4.7）。LLM 统一重试 + 伪响应兜底 + 失败落盘带 caller 定位；每个 UI 区块独立异常边界；flash 提示跨 rerun 存活；演示模式图谱/综述双层兜底且诚实标注"演示模式"；无 Key 离线链路完整可用。实测 7/7 条演示路径 0 未捕获异常、9 页面 + 9 项故障注入 UI 冒烟 exception=0——这是评审现场最直接的护城河。

7.2 应用创新点

  1. 真实被引数据链路与"不编造"纪律（实现详见 4.2.4 / 4.3.5）。引用含金量不是规则拍脑袋：DOI/arXiv ID 精确匹配优先且带标题复核（实测拦截了 OpenAlex 的错指 DOI）、三级数据源降级、被引数优先选优（修复同名噪声记录反超，AlexNet 被引数 760 → 108512 与真值一致）、限流降级显式打 low_confidence 标注、三级全失败返回 None 并写明"该维度不计分、不猜测"。这套"宁缺毋假"的数据纪律同样应用于 GitHub 复现性评分与 Future Work 判定。
  2. 图谱驱动的综述与前沿判定。综述不把摘要堆给 LLM，而是注入社区发现簇/时间线/骨干边/PageRank 结构，LLM 不可用时用同一图结构确定性生成四段式综述（保证离线演示可讲）；前沿论文五维打分（含外部真实被引）替代"入度=0 即边缘"的朴素规则，并显式排除孤立噪声节点。
  3. 诚实降级作为产品设计。LaTeX 无编译器 → 源码 + 在线编辑链接；Graphviz 无依赖 → 零依赖 DOT→SVG 等价拓扑图并明示"降级渲染"；参考文献抽取质量不足 → 直接判失败回退并标注，不拿索引页凑数；多模态 Key 不可用 → 扫描件明确拒入而非假装识别成功（15 页耗时 140.06s → 0.63s）。系统的每一处降级都在 UI 上说明"发生了什么 + 可能原因 + 怎么办"。

8.1.3 一句话总结

本项目不是把通用大模型套一层学术皮肤，而是围绕"科研结论必须可溯源、不可编造"这一约束，从零设计并实现了整套工程链路：用版面感知解析保证进入向量库的上下文不串栏，用四道防线让"不知道"能被系统诚实说出并拒答，用真实外部数据源（OpenAlex/S2/Crossref/GitHub）替代规则打分，用统一降级矩阵保证任何外部依赖失效时都"明示而不静默"。

在技术取舍上我们有一条贯穿始终的纪律：宁缺毋假——被引数取不到就写明"该维度不计分"，OCR 不可用就明确拒绝空扫描件入库，参考文献抽取质量不足就直接判失败而不拿索引页凑数。这条纪律让部分数字看起来不够漂亮（例如 v1/v7 整篇相似度仅 0.891292 低于阈值，靠分段指纹 0.963228 才命中），但它保证了评委看到的每一个数字都能被复现。

当前状态是可演示、可复现、可审计：一句话启动（streamlit run app.py），无 API Key 也能跑完解析、检索、去重、图谱、离线综述等全部链路；每一个关键指标都有对应的复跑脚本与实测报告。余下的不足已诚实列在 8.2，改进路径列在 8.3。
