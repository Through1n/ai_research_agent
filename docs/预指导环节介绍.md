## 〇、本环节的定位

「预指导」是赛程中的环节名。按**正常比赛模式**理解：预指导是正式路演/决赛之前的
一次项目说明环节，参赛队提交**材料 + 视频**，向组委会专家说明项目现状，
供专家了解项目、指出问题、给出指导建议。

因此本材料的写法是「**给专家看的、能被追问的**」：先说清楚是什么，再说清楚怎么自己
验证，最后把做不好的地方摆到台面上——**专家的指导建议必须建立在准确信息上**，
把边界藏起来只会让建议跑偏。

> 本环节按常规标准准备：材料书面可读、视频按时长可录、讲解可照稿讲。
> 若赛程对该环节另有细则（例如限时更长或需要现场答辩），**只需调整时长**——
> 第二至第五节与视频分镜均可直接复用；视频脚本第三节已给出
> 2:00 / 3:30 / 5:00 三种时长的增删方案。

## 一、目的

1. **让专家在 3 分钟内建立正确认知**：知道 MoreHand 是什么、解决什么科研痛点，
   核心差异化在哪里——不被「又一个 RAG 问答壳」的第一印象带偏。
2. **给出可当场验证的上手路径**：让专家能用最低成本自己跑一遍、自己判断真假，
   而不是只能听我们讲。**能被复现的说明才有讨论价值。**
3. **把边界讲在前面，主动给出改进建议的靶子**：本项目有明确的能力边界
   （第三节要点 5），这些正是预指导最可能给出建议的方向，先说清楚比被问出来更好。

## 三、核心要点

> 每条 = **结论 → 证据 → 边界**。讲解时按这个顺序说，专家追问时正好有下一层可答。

### 要点 1 · 它是什么：意图驱动的科研全流程智能体，不是通用大模型套一层学术皮肤

- **结论**：9 个交互页面 + 一个真正的智能体内核（任务规划、多专家路由、函数调用闭环、
  三层护栏），覆盖「传文献 → 读 → 问 → 检索 → 追 → 图谱 → 写」全流程。
- **证据**：导航 9 项定义在 `MENU@ui/sidebar.py:15`；22 个工具全部接入 6 专家白名单、
  无孤岛（`build_registry@tools/definitions.py:379`）；UI 冒烟 9 页 0 未捕获异常。
- **边界**：智能体内核的「规划」依赖模型能力，离线无 Key 时只走确定性链路。

### 要点 2 · 核心差异化：宁缺毋假——把「答错能不能被抓出来」做成代码判定

这是本项目最该被看见的一条，也是**最该被追问**的一条。四道防线跨生成前中后：

| 防线 | 机制 | 实测 |
|---|---|---|
| 生成前 · 拒答闸门 | 最高相关度低于 0.35 直接拒答，**一次模型调用都不发** | 无关问题 top=0.1820，**0 次 LLM 调用**（`RELEVANCE_FLOOR@services/rag.py:46`） |
| 生成时 · 角标约束 | 强制每条事实带来源角标 | 细粒度三问全命中真值：Adam β1/β2=0.9/0.98、8×P100、BLEU 28.4/41.8，**溯源 6/6 带页码** |
| 生成后 · 逐句校验 | 逐句算锚点覆盖率，低于阈值判可疑 | 真实句覆盖率 84.5% 通过，编造句 10% 被标记（`check_citation_support@core/guardrails.py:96`） |
| 收尾 · 确定性拼接 | 参考文献由系统拼，模型**没有机会碰** | 40 条参考文献**逐字一致 40/40**、占位符 0 处、14364 字、44.6s（`build_references_section@services/writing.py:195`） |

- **为什么值得说**：竞品比「答得好不好」，我们比「**答错了能不能被抓出来**」。
- **边界**：锚点只取英文词与数字，**纯中文句锚点少于 2 个时跳过判定**（`_anchor_tokens@core/guardrails.py:51`）——中文问答场景下防线二覆盖率下降。

### 要点 3 · 技术纵深在解析层：先保住版式，再谈检索

- **结论**：通用 RAG 直接按文本流切块，会把双栏论文的左右栏搅在一起。我们先做
  版面感知解析（双栏几何判定、扫描件识别、图↔图注关联、标题树、参考文献抽取），
  再切块入库。
- **证据**：
  - 双栏判定要求 4 条必要条件同时成立（横跨否决、空白带采样、栏宽平衡、两侧块数），
    单栏语料 1111 页误判率 **19.1% → 0%**，真双栏 BERT 正文页 **10/10** 正确识别
    （`_detect_two_columns@services/parsing.py:196`）；
  - 541 页官方教材（22MB）**537 页提取 / 1305 文本块 / 25.32s / 峰值 893.1MB / 0 失败页**；
  - 图表公式保留，表格文本化进块，引用 ↔ 参考文献**双向跳转 36/36 锚点、死链 0**。
- **边界**：三栏与跨栏表格仍可能判错，判错时保守回退单栏——不崩、不阻断，但精度会掉。

### 要点 4 · 可复现、可审计：每个数字都有复跑脚本

这是预指导环节**最该被利用**的一条：专家不必相信我们，可以自己复跑。

| 事实 | 数字 | 复跑命令 |
|---|---|---|
| 单元测试 | **238/238** | `python -m unittest discover -s tests` |
| UI 冒烟 | 9 页 + 9 项故障注入，**0 未捕获异常** | `python scripts/_smoke_ui.py` |
| 阅读页专项 | **62/62 PASS** | `python scripts/_smoke_read.py` |
| 真实 API 链路 | **21/21 PASS** | `python scripts/_verify_live_api.py` |
| 技术文档代码引用 | **236 条引用，0 疑似错误、0 无法判定** | `python scripts/_check_doc_refs.py` |

- 另有一键复现：`start.bat`（Windows）/ `start.sh`（macOS、Linux）/`Dockerfile.quick`；
  侧栏「一键加载演示数据（6 篇）」可**无 Key** 跑通离线链路；
  5 家模型平台可热切换（`PROVIDERS@core/providers.py:33`），走同一套 OpenAI 兼容协议。
- **边界**：21/21 依赖真实 Key 与外网；**无 Key 时只覆盖离线链路**。

### 要点 5 · 诚实的边界（先摆出来，请专家直接指教）

1. **未覆盖赛题「20 篇批量文献」规模**：本地语料按 arXiv 号合并后只有 2–3 个逻辑节点、
   **1 条真实引用边**，图谱指标在小语料下仅供参考。**我们没有宣称支持 20 篇**；
   `scripts/bench_graph.py` 提供 n=20/n=40 建图压测（近几轮未重复实测，旧值仅作参考）。
2. **纯中文句的引用校验盲区**（见要点 2 边界）。
3. **并发写库无文件锁**：容器每会话一份，但写库是整体覆盖，短期待遇并发上传有丢块风险，
   建议 UI 层串行化入库（已写进 Roadmap）。
4. **扫描件依赖带视觉能力的平台**：内置 5 家里深度求索与本地离线模型**没有视觉能力**，
   换到这两家时扫描件是**直接拒收入库**（`scanned_no_ocr`），不是「降级但还能用」。
5. **中文向量偏弱**：v1/v7 整篇相似度 0.891292 够不上 0.90 阈值，靠分段指纹兜底
   （`drop_stale_versions@services/rag.py:91` 的版本仲裁同理：新版进池不足 3 条就留旧版）。

## 四、操作步骤

### 4.1 专家自验路径（5 分钟，五步；全程无需注册、无需登录）

| 步 | 动作 | 应看到什么 | 需要什么 |
|---|---|---|---|
| 1 | 打开仓库首页 `README.md`，读标题下那句定位 | 知道它是科研全流程智能体 | 浏览器 |
| 2 | 看主界面截图 7 张（`docs/shots/p0–p6`） | 界面长什么样 | 浏览器 |
| 3 | 本地跑：`git clone` 后双击 `start.bat`（或 `start.sh` / `docker compose up -d`） | 脚本自动定位环境、装依赖、起服务并打开浏览器 | conda 或 Docker |
| 4 | 侧栏拉到底 → 点「**一键加载演示数据（6 篇）**」 | `✅ 演示数据已就绪，当前文献库 6 篇` | 无需 Key |
| 5 | 进「跨文献问答与溯源」→ 输入「**训练用了什么 GPU？数量和型号？**」→ 点「提问」 | 答案带来源角标 + 溯源卡，点角标可跳到原文页码 | 无需 Key（走本地召回） |

> 第 4–5 步是**最短验证路径**：不装任何东西也能看到「有文献库、有答案、有溯源」。

**想验真跑能力（需自备智谱 Key）**：侧栏「模型接入与账号」填 Key → 点「🔌 测试连通性」
→ 提问观察真实模型链路；上传一个扫描件 PDF 看光学字符识别（需带视觉能力的平台）。

### 4.2 现场讲解的演示路径（3 分钟操作，与视频分镜一致）

| 顺序 | 操作 | 画面重点 |
|---|---|---|
| ① | 侧栏点「**跨文献问答与溯源**」 | 输入框与「提问」按钮 |
| ② | 贴入问题 → 点「提问」→ 等答案 | 答案里的**来源角标** |
| ③ | 鼠标划过角标 / 点「定位第 N 页」 | 溯源卡跳转到**原文页码与段落** |
| ④ | 切「**文献库管理**」→ 看 6 篇条目的页数与文本块数 | 表格里真实的页数与块数 |
| ⑤ | 切「**版式阅读与智能翻译**」→ 选 BERT → 点「检测本页栏数」 | 双栏判定结果（真双栏） |
| ⑥ | 切「**引用图谱与综述**」→ 展开「渲染设置」→ 点「🎭 演示模式示意图谱」 | 图出现；**口播必须说明这是按主题相似度生成的示意关系，不是真实引用边** |

> ⑥ 的诚实说明很重要：真实引用边在当前小语料下只有 1 条，**主动说破比被问出来好**。
> **注意**：这一步是**现场讲解专用，不进视频**——既有录制规范 R7 明确禁止在正片里用
> 演示模式示意图谱兜底（`docs/录制工程化脚本.md` 第四节），预指导视频因此不讲图谱。

### 4.3 录制前预热（照 `docs/预指导视频脚本.md` 第一节执行）

- 模型调用有 10–30 秒延迟，**录制当天必须先把要用到的动作各跑一遍**并留在会话里；
  **预跑完不要重启应用、不要刷新页面**（Streamlit 的问答历史、翻译快照、图谱结果都活在会话里）。
- **录制当天照 `docs/预指导视频脚本.md` 顶部的「★ 速查卡」执行**——那一页可单独打印，
  贴在屏幕旁照着做；准备阶段的细节在视频脚本第一节。
