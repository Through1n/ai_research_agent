## 三、录制技术参数建议

| 项目 | 建议值 | 说明 |
|---|---|---|
| 分辨率 | **1920 × 1080**（1080p）及以上 | 赛题硬指标"不低于 1080p"。若显示器是 4K，按 1080p 录制即可，4K 文件过大不利上传 |
| 帧率 | **30 fps**（恒定） | 60fps 文件翻倍但评审看不出差别；务必选"恒定帧率"而非"可变帧率"，否则后期拼接会音画不同步 |
| 编码器 | **H.264（AVC）** | 兼容性最好。H.265 体积小但部分评审机器放不了 |
| 封装/格式 | **MP4**（`.mp4`） | 赛题硬指标 |
| 码率 | 8–12 Mbps（CBR 或 VBR 上限 12M） | 1080p30 下画面细节足够，7 分钟约 500MB 以内 |
| 音频 | AAC，48kHz，单声道即可，128–192 kbps | 旁白为主，不需要立体声 |
| 色彩 | 全屏 honest F11，浏览器缩放 100% | 确保图标、按钮文字不糊 |

## 四、录制工具与字幕配音建议

**录屏工具（任选其一）**

| 工具 | 平台 | 推荐理由 |
|---|---|---|
| **OBS Studio**（首选） | Win/macOS/Linux | 免费开源；在 `设置 → 视频` 里把"输出分辨率"设为 1920×1080、帧率设为 30；`设置 → 输出 → 录像格式` 选 `mp4`，编码器选 `x264`；支持"仅捕获浏览器窗口"，避免误录桌面 |
| ShareX | Windows | 极轻量，适合"一次录一段"的分镜策略；用 `ffmpeg` 作为录制后端可直接出 mp4 |
| 剪映 / Camtasia | Win/macOS | 录制 + 剪辑 + 字幕一条龙，适合不想折腾参数 |
| QuickTime + ffmpeg | macOS | `ffmpeg -i in.mov -c:v libx264 -crf 20 -pix_fmt yuv420p -r 30 out.mp4` 转码 |

**字幕与配音**

- **字幕硬性利器**：全程加中文字幕（可用剪映"智能字幕"自动生成后人工校正）。术语要改对：`① Agent（智能体）、② Function Calling（函数调用）、③ RAG（检索增强生成）、④ Token（词元）、⑤ Transformer/BERT/Adam 保持英文原样`。
- **不要用机器配音**：赛题明确要求"普通话讲解"，机器配音容易被判不满足真人讲解要求。真人录，环境安静，嘴距麦克风 15–20cm。
- **分段录再拼**：严格按上面 10 段单独录。某段说错只重录这一段，不要追求一镜到底——这是最省时间的做法。
- **音画分离技巧**：先用上面的台词录一遍纯语音，听着顺，再对着语音讲一遍录屏，最后替换音轨。比边操作边说流畅得多。
- 每个功能演示操作前，先停 1 秒、光标悬停在按钮上，方便后期加"点这里"的箭头标注。

## 五、翻车预案（每个环节的救场方案）

> **总原则：永远不要把错误念成"这是我们的 bug"。** 所有失败都先指向"外部依赖"，再顺势讲"所以我们做了降级与兜底"——降级能力本身就是评分点。

| 编号 | 故障现象 | 现场操作 | 备选话术（直接念） |
|---|---|---|---|
| P0 | 应用起不来 / 白屏 | `Ctrl+C` 重启；仍不行则 `conda activate ai_research` → `python -m streamlit run app.py`；极端情况下直接切预先录好的备用视频 | "本地环境问题，我们切换到预先录制的环境继续演示。" |
