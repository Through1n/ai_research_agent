## 一、跑起来（评委第一关）

### Q1. 我电脑上什么都没装，怎么看？

三条路，任选一条，都不需要注册账号：

| 路径 | 命令 / 操作 | 耗时 | 适合谁 |
|---|---|---|---|
| **A. 在线演示地址** | 浏览器打开 **https://ai4s-research-agent.app.workbuddy.host/** | 0 分钟 | 所有人首选 |
| **B. Docker** | `docker build -f Dockerfile.quick -t ai4s-quick .`<br>`docker run --rm -p 8501:8501 ai4s-quick` | 构建 5–10 分钟 | 本机有 Docker |
| **C. 一键脚本** | Windows 双击 `start.bat`；macOS/Linux `./start.sh` | 首次 3–8 分钟 | 想验证源码可复现 |

> Docker 镜像**启动时自动加载演示数据**（`Dockerfile.quick` 的 CMD 先跑 `_quick_load_demo.py`），
> 打开浏览器就是「文献库 3 篇」的可用状态，侧边栏按钮都不用点。

### Q2. 我没有智谱 / OpenAI 的 API Key，能看什么？

**能看绝大部分，而且不会坏。** 系统把功能切成两条独立的链：

| 链路 | 需要 Key？ | 包含 |
|---|---|---|
| **本地链路** | 否 | PDF 解析 · 切块 · 混合检索（向量 + BM25）· 语义查重 · 引用图谱 · 版本管理 · 写作出图 · 版式阅读翻译 |
| **大模型链路** | 是 | 跨文献问答的答案生成 · 智能翻译润色 · Future Work 扫描 · 写作建议 |

无 Key 时点大模型功能，会给出**明确的中文降级提示**（含「无 Key 时可点『🚀 一键加载演示数据』用本地离线链路继续演示」的引导，见 `ui/common.py:438`），
而不是白屏或报错栈。

### Q3. 侧边栏那个「🚀 一键加载演示数据」点了会发生什么？

向文献库写入 **3 篇内置示例论文**（`config.py:147` `DEMO_PAPERS`）：

| 文件 | 论文 | 用途 |
|---|---|---|
| `1706.03762v7.pdf` | Attention Is All You Need (v7) | 与 v1 配对做**同文多版本去重与差异对比** |
| `1810.04805v2.pdf` | BERT | 与上篇有真实引用关系，用于**引用图谱** |
| `data.csv` | 示例数据表 | 写作页「📂 载入示例数据」自动出图 |

**幂等**：已加载过的不重复写入（`ui/sidebar.py:431` `if fn not in ctx.files`），
同一份 storage 反复重启不会灌重复数据。点完看到顶部 `✅ 演示数据已就绪，当前文献库 3 篇` 即成功。

### Q4. 双击 `start.bat` 闪退 / 没反应？

按出现的信息对号入座：

| 现象 | 原因 | 处置 |
|---|---|---|
| 黑窗口一闪就没 | 被安全软件拦截，或脚本不在项目根目录 | 确认 `start.bat` 与 `app.py` 同级；加白名单后重试 |
| 「没找到 app.py」 | 脚本被单独拷走了 | 整个项目目录一起拷贝，不要只拿脚本 |
| 「没有检测到 conda」 | 本机没装 conda | 装 Miniconda 后重跑；**或直接改用在线演示地址 / Docker** |
| 卡在 pip 安装很久 | 首次装依赖 | 正常，2–5 分钟；想加速换清华源：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| 「端口提示跳到 8502」 | 8501 被占用 | 脚本会自动依次试 8502–8510，**用黑窗口里给的新地址即可，不是故障** |
| 浏览器开了但打不开 | Streamlit 还在预热 | 等 5 秒刷新一次 |

### Q5. `start.bat` / `start.sh` 安全吗？会不会偷我的 Key？

**不会。** 两条硬约束，可以当场翻源码核对：

1. 脚本里**不含任何真实 API Key**，只有判断「有没有」的逻辑：
   - `start.sh:145-146` 用 `grep -Eq '^[[:space:]]*ZHIPU_API_KEY=.+' .env` 只做存在性匹配；
   - `start.bat:173-176` 用 `findstr /r /c:"ZHIPU_API_KEY=."` 同理。
2. 检测到 Key 后只打印「✓ 已检测到 API Key（为安全起见，此处不显示任何内容）」，
   **不回显、不读取内容、不外传**（`start.sh:150`、`start.bat:180`）。

> 也可以在网页侧边栏临时填 Key，仅存于会话内存，不落盘（`ui/sidebar.py` 的 Key 输入区）。

### Q7. 没填 Key 时，问答页给出的答案是大模型生成的吗？

**不是，而且系统明确告诉你了。** 无 Key 走本地召回降级，答案区会出现
**`⚠️ 离线占位响应` 橙色标识条**，写明「这段不是模型生成的，别引用」。

这是本项目的一条设计红线：**失败与降级必须可见，不能偷偷编一段看起来像模像样的答案混过去。**
同理，引用图谱的演示模式也会标注「依据主题相似度生成，**不代表真实引用关系**」（`ui/page_graph.py:139`）。

### Q8. 「🎭 演示模式示意图谱」出来的图是真的引用关系吗？

**不是。** 按钮名字和结果区都写清楚了：它依据**主题相似度**生成，用于在
「论文正文没有 References 章节 / 演示语料引用条目过少」时兜底展示图谱交互，
**不代表真实引用关系**（`ui/page_graph.py:139`、`:268`）。

想看真实引用关系：上传含完整参考文献的 PDF（如 BERT 与 Transformer 两篇），
点「🕸️ 构建引用图谱」，成功时会提示 `✅ 图谱构建完成：N 个节点 · M 条真实引用关系`（`ui/page_graph.py:213`、`:235`）。

### Q9. 写作页的图表是从我传的数据真生成的，还是写死的图片？

**真生成。** 传一份 CSV（或点「📂 载入示例数据」，`ui/page_writing.py:104`），
系统按数据内容选渲染后端，链路在 `services/writing.py:1506-1544`：

```
graphviz 包 → dot -Tsvg → matplotlib(PNG) → 零依赖 DOT→SVG
```

**为什么 `requirements.txt` 故意不装 matplotlib**：装了反而更差——matplotlib 默认字体无 CJK，
中文标签会渲染成方框 □；不装会落到最后一级「零依赖 DOT→SVG」，由浏览器渲染，**中文正常**。
Docker 镜像因为装了 graphviz 系统包，走 `dot -Tsvg`，也用不到 matplotlib。

### Q10. 系统支持哪些大模型？只能智谱吗？

**不限一家。** 侧边栏预设五家 + 自定义任意 OpenAI 兼容端点
（vLLM / LM Studio / 硅基流动 / 校内网关，见 `ui/sidebar.py:165` 的说明文案）。
默认配置是智谱 `glm-4-flash`（文本/规划）+ `glm-4v`（多模态/OCR），见 `config.py:121-122`。

## 三、技术实现（评委第三关）

### Q11. 向量化用的是什么模型？中文问题能检索英文论文吗？

用的是 **chroma 自带的 `ONNXMiniLM_L6_V2`**（384 维，英文预训练），
在 `services/state.py:43` 的 `_build_embed_fn()` 里实例化，**全程本地推理、不调用任何外部 Embedding API**。

这一点我们主动说明，因为它是个**已知的取舍**而不是疏漏：
- 好处：零配置、离线可用、无额外依赖、首问等待已被挪到启动期（`services/state.py:59` 的 warmup）；
- 代价：跨语言语义匹配弱于中文专用模型，所以**不能只靠向量**——这正是要做混合检索的原因（见 Q12）。

### Q12. 混合检索具体怎么混合的？

两路并行召回 + 融合，参数全在 `config.py:134-140`：

| 参数 | 值 | 含义 |
|---|---|---|
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | 1200 / 150 | 切块目标字符数与重叠 |
| `DENSE_K` | 12 | 向量（语义）召回数 |
| `SPARSE_K` | 12 | BM25（关键词）召回数 |
| `FINAL_K` | 6 | 融合后进入 LLM 上下文的片段数 |
| `DEDUP_THRESHOLD` | 0.90 | 语义去重相似度阈值 |

**为什么必须两路都要**：向量路强在语义、弱在专有名词和数字（Q11 已说明跨语言短板）；
BM25 强在精确词面匹配。两路互补，融合后才同时扛得住「Transformer 的核心创新」这种语义问句
和「28.4 BLEU」这种精确数值问句。

### Q13. 「抗幻觉」具体做了哪些事？给可验证的清单

| 手段 | 做法 | 在哪 |
|---|---|---|
| 引用角标 | 每句结论挂 `【n】`，可回溯到原文页/段 | 问答页来源卡片 |
| 数字校验 | 答案里的数字逐个回文献核对，对不上就标出来 | `services/rag.py` `find_unverified_numbers` |
| 降级可见 | 无 Key / 超时 / 限流都给**明确中文标识**，不冒充模型输出 | `ui/common.py` 降级提示体系 |
| 图谱诚实标注 | 演示模式明说「不代表真实引用关系」 | `ui/page_graph.py:139` |
| 超时预算 | 单次 45s / 总预算 20s，失败最坏约 45s 降级，不在台上长时间转圈 | `config.py:123`、`:128` |

### Q14. 测试覆盖如何？给个数

`python -m unittest discover -s tests` → **18 条全部通过**（`tests/test_core.py`）。
另有页面渲染冒烟与阅读页冒烟两个脚本（`scripts/_smoke_ui.py`、`scripts/_smoke_read.py`），
以及文档引用校验器（`scripts/_check_doc_refs.py`，当前 238 条引用 0 疑似）。

我们如实说明边界：**单测 18 条覆盖不到全部路径**，所以文档里所有 `文件:行号` 断言

## 四、工程与部署（评委第四关）

### Q16. 在线部署用什么平台？入口文件为什么是 `streamlit_app.py`？

**Streamlit Community Cloud**（`docs/部署操作手册.md` 五步）。

平台约定入口文件叫 `streamlit_app.py`，而本项目主脚本是 `app.py`。没有改主脚本名，
而是加了一个 6 行引导文件（仓库根 `streamlit_app.py`）：

```python
import os
import runpy
runpy.run_path(
    os.path.join(os.path.dirname(os.path.abspath(__file__)), "app.py"),
    run_name="__main__",
)
```

**为什么不直接 `import app`**：`app.py` 顶层有 Streamlit 副作用与 `st.set_page_config`，
import 会触发「set_page_config 只能调用一次」一类问题。`runpy` 以 `__main__` 身份执行，
与本地 `streamlit run app.py` 行为完全一致（已用 AppTest 双路对比验证 0 异常）。

### Q17. 云平台的 Key 怎么管？会提交进仓库吗？

**不会。** `.env` 在 `.gitignore` 里；云平台用 **Streamlit Cloud Secrets** 界面填，
本地通过 `config.py` 的 `_env_str` 按 `os.environ → st.secrets → 默认值` 顺序读取
（即同一份代码本地/云端都能跑）。模板见 `.streamlit/secrets.toml.example`。

### Q18. `storage/` 目录是什么？为什么仓库里没有？

运行时数据（向量库、上传文件、缓存、日志），`.gitignore` 已忽略。
**不需要手动建**：`config.py:38-42` 启动时 `mkdir(parents=True, exist_ok=True`。
Docker 镜像里则预置了三个零崩溃种子文件（`Dockerfile.quick` 第 4 层），
类型约束来自 `services/state.py` / `core/memory.py` 的实际读取方式。

### Q19. 有个 `HF_ENDPOINT` 镜像开关，云平台会不会踩坑？

**已修掉，这是本轮发现并解决的一个真实部署阻断点。** 原实现无条件设
`https://hf-mirror.com`；Streamlit Cloud 服务器在境外，连国内镜像更慢 / 易超时，
会导致 chroma 首次下载 embedding 模型时挂住。现在改为**仅桌面态启用镜像**
（`config.py:131`：`if DESKTOP_MODE: os.environ.setdefault(...)`），
云平台留空走 `huggingface.co`。Docker 侧另有构建期 ONNX 预热兜底（`Dockerfile.quick` 第 5 层）。

### Q20. 提交历史看起来是断续的，是一次性赶工吗？

**是 5 天 87 次提交的连续开发**，叙事断层与超大提交的逐条分析见
`docs/提交历史分析.md` 与 `docs/提交历史阅读指南.md`（含 9 处叙事断层的定位和 14 个超大提交的说明）。
我们如实记录了三个待改进项：提交作者邮箱是占位符、部分提交粒度偏大、
有一条提交信息里的提交数与实际不符——这些都在分析文档里点名了，没有粉饰。

## 六、隐私与数据

### Q21. 我在网页里填的 API Key / 上传的 PDF 会去哪？

- **API Key**：只进当前会话内存 / 本地 `.env`（gitignored）。启动脚本只做存在性判断，
  不回显不外传（见 Q5）。云端走 Streamlit Secrets。
- **上传的 PDF**：只落在本机 / 容器 `storage/uploads/`，解析在本地完成。
  引用图谱若开启外部元数据补全会走 OpenAlex（可填 `OPENALEX_MAILTO` 提升限额），
  除此之外**没有把文献内容发送到第三方的逻辑**。

### Q22. 演示数据是哪来的？会不会有版权问题？

内置 3 篇均为 **arXiv 公开论文**（Transformer v7 / BERT v2，原始 PDF 就在 `demo_data/`），
`data.csv` 是自造的示例表格。没有抓取任何付费墙内容。
