# 部署操作手册：Streamlit Community Cloud 上线

> 目标：把本仓库部署成一个**真实可访问的公开演示地址**，供评委直接打开。
> 本手册是「照着点就能成」的操作步骤，不是原理说明。
> 前置检查结论已实测（见 §0），无需再猜。

---

## §0 部署前置检查（已实测，逐条对照）

| 检查项 | Cloud 要求 | 本仓库实测 | 结论 |
|---|---|---|---|
| 仓库可见性 | 必须是**公开** GitHub 仓库 | `Through1n/ai_research_agent`（已 push 成功） | ✅ 满足 |
| 依赖清单 | 根目录 `requirements.txt` | 存在，1215 字节，14 个依赖 | ✅ 满足 |
| 主入口文件 | 默认找 `streamlit_app.py` | 主脚本是 `app.py`，**默认名不匹配** | ⚠️ 已处理 |
| 密钥 | 不得入库 | `.env` 与 `.streamlit/secrets.toml` 均已被 `.gitignore` 排除 | ✅ 安全 |

### 关于入口文件（本轮已修复）

仓库根已新增 **`streamlit_app.py`** —— 它是一个引导文件，用 `runpy.run_path(..., run_name="__main__")`
以 `__main__` 身份执行 `app.py`，行为与 `streamlit run app.py` 完全一致。

因此部署时**无需手动指定入口**，Cloud 会自动找到它。

> 等价替代方案（二选一，不必都做）：
> 若更愿意保留单一入口，可在 Cloud 部署对话框里把「Main file path」显式填成 `app.py`，
> 然后删掉 `streamlit_app.py`。两种做法不会同时生效冲突，但只保留一种更整洁。

## 第一步：登录 share.streamlit.io

**在哪里操作**：浏览器打开 `https://share.streamlit.io`，点右上角 **Sign in**。

**截图位置**：页面右上角头像区域；登录成功后头像会显示你的 GitHub 头像。

| 现象 | 原因 / 处置 |
|---|---|
| 一直卡在「Continue with GitHub」 | 浏览器拦截了第三方 Cookie，换无痕窗口或允许 Cookie |
| 登录后头像不显示 | 刷新一次即可，不影响部署 |
| 提示邮箱未验证 | 先去 GitHub 完成邮箱验证再回来 |

## 第二步：授权 GitHub

**在哪里操作**：登录页点 **Continue with GitHub** → GitHub 的 OAuth 授权页点 **Authorize**。

**截图位置**：GitHub 授权页中部的绿色 Authorize 按钮。

| 现象 | 原因 / 处置 |
|---|---|
| 授权后跳转到 Streamlit 但看不到仓库 | 授权范围不够，去 GitHub `Settings → Applications → Streamlit` 重新授权并勾选仓库读取权限 |
| 提示需要申请访问私有仓库 | 本项目是公开仓库，确认仓库 Visibility 为 Public |

## 第三步：选择仓库、分支与入口文件

**在哪里操作**：登录后右上角 **New app** → 填入三项：

| 字段 | 填什么 |
|---|---|
| Repository | `Through1n/ai_research_agent` |
| Branch | `main` |
| Main file path | `streamlit_app.py`（**已存在**；也可填 `app.py`，二选一） |

**截图位置**：「New app」表单中部的三个输入框，以及下方的 Deploy 按钮。

| 现象 | 原因 / 处置 |
|---|---|
| Repository 下拉里找不到本仓库 | ① 仓库非 Public；② GitHub 授权未包含该仓库 → 重新授权 |
| 报 `Main file path not found` | 路径填错。确认根目录存在 `streamlit_app.py`（已新增）或 `app.py` |
| 部署后页面一直「Running…」转圈 | 多为端口/地址绑定问题 → 见 §常见报错 R1 |

## 第四步：填 Secrets（关键，否则整站静默降级）

**在哪里操作**：
`App 页面右下角「⋯」→ Settings → Secrets`
（路径：App 主界面 → 右下角三个点 → Settings → 左侧 Secrets 选项卡）

**截图位置**：Settings 弹窗左侧「Secrets」菜单项，右侧为多行文本编辑框。

把 `.streamlit/secrets.toml.example` 的内容整段粘贴进去，然后**只替换 Key 值**：

```toml
LLM_PROVIDER = "zhipu"
ZHIPU_API_KEY = "你的真实智谱key"
```

点 **Save**，平台会自动重启应用（约 30–60 秒）。

> **为什么必须在 Cloud 后台填**：`.env` 被 `.gitignore` 排除，推到云端后**根本不存在**。
> 若不填 Secrets，代码一个 Key 都拿不到，整站会静默降级成「离线模式」——
> 评委看到的就是所有 AI 功能不可用。这是本轮最容易被忽略、也最致命的一步。

| 现象 | 原因 / 处置 |
|---|---|
| 页面提示「未配置 API Key」 | Secrets 没保存或键名写错（必须是大写，如 `ZHIPU_API_KEY`） |
| 填了 Key 仍提示无效 | ① Key 过期/额度用尽；② 复制时带空格 → 检查 `ZHIPU_API_KEY` 值 |
| Save 后无反应 | 检查 TOML 语法：值必须带引号，不能出现裸冒号 |

---

## 第五步：点 Deploy

**在哪里操作**：表单底部 **Deploy!** 按钮。

**截图位置**：New app 表单最下方的 Deploy 按钮；点击后进入部署日志页。

首次部署耗时约 **3–8 分钟**（安装依赖 + 首次下载 embedding 模型）。

| 现象 | 原因 / 处置 |
|---|---|
| 部署日志停在 `Installing dependencies` | 正常，依赖较多（chromadb/pandas 等），等 5–10 分钟 |
| 报 `ModuleNotFoundError` | 依赖未写入 `requirements.txt` → 补上后 Redeploy |
| 报内存不足 | chromadb + pandas 较吃内存，换 HF Spaces 或自建 |
| 首次打开检索功能极慢 | chroma 首次下载 embedding 模型，见 §常见报错 R2 |

## §常见报错速查

| 编号 | 报错 / 现象 | 根因 | 处置 |
|---|---|---|---|
| R1 | 页面一直转圈打不开 | `config.toml` 里写死了 `server.address` | 本项目已**故意注释掉** address（`.streamlit/config.toml`），交由平台决定；勿取消注释 |
| R2 | 首次检索卡住 / 超时 | `HF_ENDPOINT` 指向国内镜像，而 Cloud 服务器在境外 | **已修复**：`config.py:131` 改为仅桌面态启用镜像；云上自动走 huggingface.co |
| R3 | 提示 Key 无效 (401) | Key 错误 / 过期 / 额度用尽 | 换 Key；或点「🚀 一键加载演示数据」走离线链路 |
| R4 | 提示限流 (429) | 请求过频 | 等 15–30 秒重试（本轮已将 429 最坏等待从 30s 压到 15s） |
| R5 | `streamlit: command not found` | 本地自建环境未装依赖 | `pip install -r requirements.txt` |
| R6 | 上传大 PDF 被拒 | `MAX_UPLOAD_MB=100` 闸门 | 换小文件或调大该环境变量 |

## §入口文件二选一说明

| 方案 | 做法 | 适用 |
|---|---|---|
| **A（当前采用）** | 仓库根保留 `streamlit_app.py` 引导文件 | Cloud 默认部署，零额外配置 |
| B | 删掉引导文件，部署时手动填 `app.py` | 想保持单一入口 |

两者都已在 `requirements.txt` / 入口逻辑上验证一致：引导文件通过 `runpy.run_path(..., run_name="__main__")` 执行，
保证 `app.py` 的模块级副作用与相对路径解析（`demo_data/`、`static/`、`.streamlit/config.toml`）不变。
