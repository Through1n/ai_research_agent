## 一、部署前必做的安全底线

> 赛题原文要求："**API 密钥不得出现在公开仓库**"。以下三条是不可协商的红线。

### 1.1 密钥只经环境变量 / 运行时注入，绝不写进任何文件

- 仓库里 **只有** `.env.example`（占位模板），真实 `.env` 已被 `.gitignore` 与 `.dockerignore` 双重排除。
- 部署前用下面命令确认没有密钥会被打包或推送：

```bash
# ① 确认 .env 不在 git 跟踪中（应无输出）
git ls-files | grep -E "^\.env$"

# ② 全仓扫描是否残留疑似密钥（应无输出；有则立刻处理）
grep -rInE "(sk-|glm-|Bearer )[A-Za-z0-9]{16,}" --include=* . \
  --exclude-dir=.git --exclude-dir=storage --exclude-dir=dist --exclude-dir=build

# ③ 确认 .gitignore / .dockerignore 仍在（每次拉取后都应复查）
ls -l .gitignore .dockerignore
```

### 1.2 密钥注入的三种正确姿势

| 方式 | 做法 | 适用路径 |
|---|---|---|
| **容器 env_file** | `docker-compose.yml` 已配 `env_file: - .env`；`.env` **只放在服务器磁盘上，不进 git** | A / B |
| **docker run -e** | `docker run -e ZHIPU_API_KEY=xxxx ...` | A / B |
| **systemd EnvironmentFile** | 单元文件里 `EnvironmentFile=/opt/ai4s/.env`，文件权限 `chmod 600` | B |

### 1.3 进阶方案：把真实密钥藏在"自建网关"后面（推荐用于公开仓库）

如果连"在服务器磁盘上放明文 Key"都不想做，可以让 **演示端完全无密钥**：

1. 在本机/另一台机器起一个 OpenAI 兼容网关（如 [One-API](https://github.com/songquanpeng/one-api)、LiteLLM），把真实上游 Key 配在网关里；
2. 演示应用在侧边栏选 `➕ 自定义端点（任意模型）`，填网关的 Base URL 与模型名，**取消勾选** `该端点需要 API Key`；
3. 网关侧配一个专用 token 或 IP 白名单限制访问。

> 代码依据：`core/providers.py` 的 `Provider.needs_key=False` 时，`resolve_key()` 直接返回占位值 `"local"`，
> 客户端正常工作。也就是说**前端可以在零密钥状态下完整演示**，真实 Key 只存在于网关一侧。

### 1.4 关于"评审专用测试账号"的正式说明

**系统当前为开放式，没有任何登录功能，评审可直接访问，无需账号密码。**

依据（全仓核实，仅命中 API Key 输入框，无任何会话鉴权代码）：

```
grep -rn "authent\|login\|st.secrets\|session_token" --include=*.py ui/ app.py services/ core/
→ 仅命中：ui/sidebar.py:134 / ui/sidebar.py:174 的 st.text_input(type="password")  # API Key 输入框
```

因此提交材料中请写：

> **在线演示为开放式访问，无需注册/登录；地址已部署，WebSocket 跨源与冷启动两项线上访问问题已修复，重部署后需复验打开效果。**
> 侧边栏已内置「🚀 一键加载演示数据（v1/v7/BERT）」，不填任何 Key 也能体验全部离线功能。

**如果赛方坚持要提供账号，两种不改业务的加法（任选，均需 15 分钟内完成）：**

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **Nginx Basic Auth**（推荐） | 见 §3.4，两条命令生成密码文件，Nginx 加两行 | 零侵入代码，随时开关 | 浏览器弹原生登录框，观感一般 |
| **Cloudflare Access / 腾讯云 CAM** | 在 CDN/接入层配一层邮箱验证码或指定邮箱白名单 | 观感专业 | 需额外接入配置 |

给评审的材料里就写成：账号 `judge` / 密码 `ai4s2026`（自定），并注明"该账号仅用于限制非评审访问，系统内部无用户体系"。

## 二、路径 A：Docker 自部署

**适用**：本机 / 实验室服务器验证；已有公网 IP 或内网穿透时也可直接对外。

### 2.1 前置条件

```bash
docker --version        # ≥ 20.10
docker compose version  # ≥ 2.0（注意是 compose v2，不是 docker-compose）
```

### 2.2 构建并运行

```bash
# ① 拉代码（仓库里不要有 .env）
git clone <your-repo-url> ai_research_agent && cd ai_research_agent

# ② 在服务器本地生成 .env（此文件只在服务器，绝不 git add）
cp .env.example .env
chmod 600 .env
# 用编辑器填 1 个 Key 即可，例如智谱（免费额度 + 唯一带视觉模型 glm-4v）
# LLM_PROVIDER=zhipu
# ZHIPU_API_KEY=<你的 Key>

# ③ 构建镜像（首次约 3–6 分钟，要拉 chromadb 等依赖）
docker compose build

# ④ 后台启动
docker compose up -d

# ⑤ 看日志，等到出现 "You can now view your Streamlit app"
docker compose logs -f ai4s-agent
# Ctrl+C 退出日志（不会停止容器）
```

访问 `http://<服务器IP>:8501`。

### 2.3 直接用 docker run（不依赖 compose，便于自定义挂载）

```bash
docker run -d \
  --name ai4s_research_agent \
  --restart unless-stopped \
  -p 8501:8501 \
  --env-file /opt/ai4s/.env \
  -v /opt/ai4s/storage:/app/storage \
  -v /opt/ai4s/deploy-config.toml:/app/.streamlit/config.toml:ro \
  ai4s-agent:latest
```

### 2.4 本项目 Docker 相关的三个关键事实（已核实，别踩坑）

| # | 事实 | 影响 |
|---|---|---|
| 1 | `Dockerfile` 的 CMD 已写死 `--server.address=0.0.0.0 --server.port=8501` | **容器内监听 0.0.0.0**，端口映射后天然可外网访问，不需要额外改配置 |
| 2 | `.dockerignore` 排除了 `.streamlit/` | 镜像里**没有** `.streamlit/config.toml`。好处：本地那条 `enableXsrfProtection = false` 不会被带到线上（默认是开的，更安全）；代价：学术风主题配色也没了。想保留主题就按 §2.3 挂载一份自定义 config.toml |
| 3 | `.dockerignore` **没有** 排除 `pdf/` 与 `demo_data/` | 官方测试 PDF（含 541 页那本）会被复制进镜像，镜像会偏大（约 1.5–2GB）。好处是**评审打开就有现成素材可点**，无需先上传。想减肥可在 `.dockerignore` 里加 `pdf/UnderstandingDeepLearning_02_09_26_C.pdf`（本次交付未改此文件） |

### 2.5 数据持久化

`docker-compose.yml` 已挂载 `./storage:/app/storage`，而：

- 向量库 `storage/chroma`（来自 `config.py: CHROMA_DIR = STORAGE_DIR / "chroma"`）
- 文献元数据 `storage/library.json`
- 长期记忆 / 画像 `storage/memory.json`、`storage/user_profile.json`
- **上传的 PDF**（`services/library.py:438` 写 `UPLOAD_DIR = storage/uploads`）

以上全部落在挂载卷里，**容器重建不丢数据**。备份只需 `tar czf backup.tgz storage/`。

## 三、路径 B：云服务器（腾讯云轻量 / 阿里云 ECS）—— 推荐

### 3.1 买什么配置

| 项 | 推荐值 | 理由 |
|---|---|---|
| 机型 | **腾讯云轻量应用服务器 2 核 4G** 或 **阿里云 ECS 共享型 s6 2核4G** | 实测 541 页入库峰值内存 283MB，4G 内存足够；2 核覆盖 3–5 人同时评审 |
| 系统盘 | SSD 60GB 起 | 镜像约 2GB，`storage/` 随上传增长，留足余量 |
| 操作系统 | **Ubuntu 22.04 LTS 64位** |apt 装 Docker/Nginx 最省事 |
| 带宽 | 3–5 Mbps 起 | 演示以文本为主，图谱是本地 `lib/` 离线渲染，带宽压力小 |
| 地域 | 选离你最近的 | —— |
| 费用参考 | 轻量 2C4G 约 ¥45–70/月；ECS 2C4G 约 ¥90–120/月；新用户首年常有 ¥24–99 优惠 | 评审期 1–2 个月即可 |

> **为什么不用 Serverless / 函数计算**：本应用是 Streamlit 长连接 WebSocket 服务，需要常驻进程，
> Serverless 冷启动会打断会话，不适合。

### 3.2 安全组 / 防火墙必须放行

| 端口 | 用途 | 是否必须放行 |
|---|---|---|
| **22** | SSH 登录 | 必须（建议改成仅你的 IP 可访问） |
| **80** | HTTP，用于 Certbot 校验与跳转 | 必须 |
| **443** | HTTPS，评审访问用 | 必须 |
| 8501 | Streamlit 直连端口 | **不要对公网开放**，只让它监听 127.0.0.1 由 Nginx 反代（见 §3.4） |

腾讯云轻量在控制台「防火墙」页配置；阿里云 ECS 在「安全组」配置。

### 3.3 装环境与起服务

```bash
# ① 装 Docker（Ubuntu 22.04）
sudo apt update && sudo apt install -y ca-certificates curl gnupg
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update && sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker $USER && newgrp docker

# ② 拉代码 + 配密钥
sudo mkdir -p /opt/ai4s && sudo chown $USER:$USER /opt/ai4s
cd /opt/ai4s && git clone <your-repo-url> app && cd app
cp .env.example .env && chmod 600 .env
# 填 Key：LLM_PROVIDER=zhipu + ZHIPU_API_KEY=...

# ③ 构建启动（这里改成只监听 127.0.0.1，让 Nginx 挡在前面）
docker compose build
docker compose up -d
```

> **关键改动**：`docker-compose.yml` 的 `ports: - "8501:8501"` 会把端口暴露到公网所有网卡。
> 想只让本机访问，改成 `ports: - "127.0.0.1:8501:8501"` 即可。
> ⚠️ 本次交付**未修改** `docker-compose.yml`（不在授权文件内），改动请自行执行：
> ```yaml
> ports:
>   - "127.0.0.1:8501:8501"
> ```

### 3.4 Nginx 反代 + 免费 HTTPS

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
```

创建 `/etc/nginx/sites-available/ai4s`：

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

server {
    listen 80;
    server_name  your-domain.example;      # ← 换成你的域名

    client_max_body_size 300m;             # 541 页 PDF 是 21MB，留足余量

    location / {
        proxy_pass         http://127.0.0.1:8501;
        proxy_http_version 1.1;

        # —— Streamlit 依赖 WebSocket，这三行不能少 ——
        proxy_set_header   Upgrade    $http_upgrade;
        proxy_set_header   Connection $connection_upgrade;

        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;

        proxy_read_timeout 300s;             # 长文档入库可能跑 30s+
        proxy_send_timeout 300s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/ai4s /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

# 申请免费证书（自动改 Nginx 配置加 443 与跳转）
sudo certbot --nginx -d your-domain.example
# 证书 90 天有效，certbot 已自动配 systemd timer 续期；可手动验证：
sudo certbot renew --dry-run
```

**（可选）Nginx Basic Auth，给评审一个"专用账号"**

```bash
sudo apt install -y apache2-utils
sudo htpasswd -c /etc/nginx/.htpasswd judge     # 输入密码，如 ai4s2026
```

在 `location / {` 内加两行：

```nginx
    auth_basic            "AI4S Research Agent - Review Only";
    auth_basic_user_file  /etc/nginx/.htpasswd;
```

然后 `sudo nginx -t && sudo systemctl reload nginx`。

### 3.5 域名怎么来

| 方案 | 做法 | 成本 |
|---|---|---|
| 有自己域名 | DNS 控制台加一条 A 记录指向服务器公网 IP | ¥0 |
| 腾讯云 DNSPod / 阿里云万网新购 | `.cn` / `.com` 首年常 ¥1–39 | ¥1–39/年 |
| **不想买域名** | 直接用 `http://<公网IP>` 也能访问（把 Nginx 里 `server_name` 改成 `_`），只是没有 HTTPS | ¥0 |

> 若坚持无域名又要 HTTPS，可用 Cloudflare 免费 CDN + 自定义域名的组合，但配置复杂度高于买一个便宜域名。

## 四、路径 C：Streamlit Community Cloud（免费，但有硬约束）

### 4.1 与"API 密钥不得公开"的冲突，以及解决之道

Streamlit Community Cloud 的部署前提是 **GitHub Public 仓库**。这带来两个必须正视的问题：

| 问题 | 说明 | 处理方案 |
|---|---|---|
| **① 仓库必须公开** | 代码、注释、`docs/` 全部可见 | 提交前务必按 §1.1 的三条命令扫一遍密钥；确认 `.env` 在 `.gitignore` 里（仓库已有 `/.env` 与 `/.env.*` 两条规则且保留 `!.env.example`，配置正确 ✅） |
| **② 密钥注入方式与本代码不匹配** | Community Cloud 官方提供的是 **Secrets（TOML）**，写入后落在 `st.secrets`；而本应用读密钥走的是 **`os.getenv`**（`config.py:65`、`core/providers.py:122`），**两者不会自动打通** | 见下方三种方案 |

**方案 C-1（推荐，零改码）：评审时在侧边栏手填 Key**

> Streamlit Cloud 的 public app 任何人都能打开侧边栏输入框，把 Key 粘贴进去即可，
> Key 只存在那次会话的内存里，**不会被写进任何文件、不会同步回 GitHub**。
> 在提交材料的"使用说明"里写清楚这一步即可。

**方案 C-2（推荐，最优雅）：用「自定义端点」+ 免密自建网关**

1. 自己搭一个 OpenAI 兼容网关（One-API / LiteLLM），真实 Key 配在网关侧；
2. 评审在侧边栏选 `➕ 自定义端点（任意模型）`，填网关 `Base URL` 与 `模型名`，
   **取消勾选** `该端点需要 API Key`；
3. 演示端彻底无密钥，Key 从不出现在任何输入框里。

**方案 C-3（无网可用时的保底）：只演示离线链路**

不配任何 Key，打开后点侧边栏 `🚀 一键加载演示数据`，
文献库、语义去重、版本管理、图谱构建等全部离线链路照常演示。

> ⚠️ **不建议**的做法：把 Key 明文写进 `secrets.toml`。虽然 Community Cloud 的 Secrets 不会进 git，
> 但一旦平台账号泄露或多个成员共享协作空间，密钥仍在他人可见范围；再者本代码读不到 secrets，
> 写了也白写。

### 4.2 部署步骤

1. 把仓库推到 GitHub **Public**（按 §1.1 复查无密钥）。
2. 打开 [share.streamlit.io](https://share.streamlit.io)，用 GitHub 账号登录。
3. 右上角 **New app** → 选仓库 / 分支 / 主文件路径填 **`app.py`** → **Deploy**。
4. 等待 3–5 分钟（首次要装 13 个依赖），得到 `https://<your-repo>-<hash>.streamlit.app`。
5. （可选）App 设置 → **Secrets**：若走了 C-2/C-3 方案，这里**留空**即可。
6. Community Cloud 会在仓库有新 push 时自动重新部署；改完代码 `git push` 即可更新。

### 4.3 Community Cloud 的三个已知限制

| 限制 | 影响 | 应对 |
|---|---|---|
| **闲置会自动休眠**（约 1 小时无访问） | 评审第一次打开会有 30–60 秒冷启动 | 在评审材料说明"首次打开请等待约 1 分钟；或使用备用地址"；评审期自己每天访问一次保活 |
| 资源上限 **1 CPU / ~1GB 内存** | 541 页长文档入库（峰值 283MB）可以跑，但慢 | 现场演示改用 15 页的 `1706.03762v7.pdf`；或提前入库、现场只展示结果 |
| 无持久化保证（`storage/` 会被重置） | 上传的文献可能消失 | 每次演示前点 `🚀 一键加载演示数据` |

> ⚠️ 因存在休眠与内存上限，**Community Cloud 只适合作为备份地址**，主用地址请走路径 A/B。

## 五、公网环境的 Streamlit 配置建议

> 本地仓库的 `.streamlit/config.toml` 是为**本机演示**调的：`address = "127.0.0.1"`、
> `enableXsrfProtection = false`、`showErrorDetails = true`。
> **这些设置不适合直接搬到公网。** 下面给出公网部署推荐值。

在服务器上新建 `/opt/ai4s/deploy-config.toml`（**不要**放仓库里，用 §2.3 的 `-v` 挂载进容器）：

```toml
[server]
headless = true
address  = "0.0.0.0"       # 容器内必须监听到全部网卡，才能被宿主机映射
port     = 8501
# 公网部署务必开启 XSRF 保护（默认即为 true，此处显式写明防被本地配置覆盖）
enableXsrfProtection = true
enableCORS           = false
# ★ CDN / Nginx 反代且用了子路径时才需要配 baseUrlPath；直接用根路径保持空
baseUrlPath          = ""
# 541 页教材 21MB，建议放宽单文件上传上限
maxUploadSize        = 300
runOnSave            = false

[browser]
gatherUsageStats = false   # 不向 Streamlit 官方回传统计数据

[client]
# 公网建议关闭错误详情：避免把堆栈、路径等信息暴露给访问者
showErrorDetails = false
toolbarMode      = "minimal"

[theme]
primaryColor                = "#1f5fae"
backgroundColor             = "#f7f9fc"
secondaryBackgroundColor    = "#eef4fb"
textColor                   = "#1d2733"
font                        = "sans-serif"
```

**为什么这么配：**

| 配置项 | 公网推荐值 | 理由 |
|---|---|---|
| `enableXsrfProtection` | **`true`** | 防跨站请求伪造。本地为方便 pywebview 桌面壳关掉了，公网必须开 |
| `enableCORS` | **`false`** | 只允许同源请求，收窄攻击面 |
| `showErrorDetails` | **`false`** | 公网不该把堆栈和服务器路径给访问者；排错改看容器日志 |
| `address` | **`0.0.0.0`**（容器内） | 容器内不监听全网卡，宿主机 `-p` 映射不通。**但宿主机映射要限制为 `127.0.0.1:8501:8501`**，把真实暴露面交给 Nginx |
| `maxUploadSize` | **300**（MB） | 541 页教材 21MB 可直接上传；也容忍评委临时传大书 |

### 6.1 进程守护（三选一）

**① Docker restart policy（已在 docker-compose.yml 里，最简单）**

```yaml
restart: unless-stopped     # 崩溃/重启服务器后自动拉起；手动 docker stop 不再自启
```

手动 append：`docker update --restart unless-stopped ai4s_research_agent`

**② systemd（不用 Docker 时的首选）**

新建 `/etc/systemd/system/ai4s.service`：

```ini
[Unit]
Description=AI4S Research Agent (Streamlit)
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/ai4s/app
EnvironmentFile=/opt/ai4s/.env
Environment="PATH=/home/ubuntu/anaconda3/envs/ai_research/bin:/usr/bin:/bin"
ExecStart=/home/ubuntu/anaconda3/envs/ai_research/bin/streamlit run app.py \
          --server.port=8501 --server.address=127.0.0.1
Restart=always
RestartSec=5
StandardOutput=append:/var/log/ai4s.out.log
StandardError=append:/var/log/ai4s.err.log

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ai4s      # enable = 开机自启

```

### 6.3 常见问题排查表

| 现象 | 可能原因 | 排查命令 / 处理 |
|---|---|---|
| 打不开、`ERR_CONNECTION_REFUSED` | 容器没起来 / 端口没通 | `docker ps -a` 看 STATUS；`ss -ltnp \| grep 8501`；看日志里的 Traceback |
| 一直转圈、30 秒后超时 | 依赖还没装完（首次构建慢） | `docker compose logs -f` 确认是否还在 pip；首次建议等 5 分钟 |
| 页面能开，图谱是空白 | 没构建图谱 | 点 `🕸️ 构建引用图谱`；无真实引用边时点 `🎭 演示模式示意图谱` |
| 问答提示"请先在左侧填入 API Key" | 没配 Key 或 provider 没就绪 | 侧边栏看是否显示 `✅ 模型已就绪`；检查 `.env` 里 key 名与所选平台是否匹配（`providers.py` 的 `key_env` 映射见 §7） |
| 上传大 PDF 失败 | Streamlit `maxUploadSize` 默认 200MB + Nginx `client_max_body_size` 默认 1MB | 见 §5 两条配置一起改 |
| 上传后报"解析失败 / 非标准排版" | PDF 加密或损坏 | 这是**预期行为**（`library._validate_prepared` 拦截"幽灵文献"）；换官方测试 PDF 重试 |
| 服务昨晚自己挂了 | OOM（内存不足） | `dmesg \| grep -i oom`；换 4G 以上机型，或减少同时评审人数 |
| 图谱拖拽很卡 | vis-network 本地 `lib/` 没进镜像 | `.dockerignore` 未排除 `lib/`，正常应存在；`docker exec <容器> ls /app/lib` 确认 |
| 证书过期 | certbot 续期失败 | `sudo certbot renew --dry-run` 排查，通常因 80 端口被占 |
| 数据全没了 | 容器被 `docker compose down -v` 删卷 | 备份即 `tar czf backup.tgz storage/`；**不要用 `-v` 参数** |

## 九、Round 13 变更与勘误（部署收尾）

### 9.1 勘误：§2.4 第 2 条「`.dockerignore` 排除了 `.streamlit/`」已不成立

当前 `.dockerignore` **只**排除 `.streamlit/secrets.toml`（第 10 行），并在第 8-9 行
明确写了「不要把整个 `.streamlit/` 排除」的理由；为防后人误加，还额外补了一条反向放行
`!.streamlit/config.toml`（第 16 行）。

因此：

- ❌ 「镜像里没有 `.streamlit/config.toml`」——**错**。镜像里有。
- ❌ 「本地那条 `enableXsrfProtection = false` 不会被带到线上（默认是开的，更安全）」——
      **这条推论也反了**：`config.toml` 进了镜像，`enableXsrfProtection = false`
      就会被带到线上。
- ✅ 好处是学术风主题配色（`[theme]` 段）与 `enableStaticServing = true` 都在，
      写作页的 mermaid 能走本地 `/app/static/mermaid.min.js`（`.dockerignore` 未排除 `static/`）。

**要收紧 XSRF**（公网部署建议）：改 `.streamlit/config.toml` 第 23 行
`enableXsrfProtection = false` → `true`，然后 `docker compose up -d --build`。
（注意 §5 那份公网配置模板第 376 行本来就写着「公网部署务必开启 XSRF 保护」，
只是它与仓库里实际生效的 config.toml 不是同一份文件，别照抄了却以为已经生效。）

### 9.2 勘误：§2.5 的引用行号 `services/library.py:438` 已漂移

上传 PDF 的落盘点现为 `services/library.py:777` `(UPLOAD_DIR / filename).write_bytes(...)`；
`UPLOAD_DIR` 本身定义在 `config.py:31`。其余三条（chroma / library.json / memory.json）的路径不变。

### 9.3 变更：§2.3 与 §2.5 的 bind mount 需要补一步 chown

`storage/` 被 `.gitignore`（第 14 行）与 `.dockerignore`（第 25 行）双重排除
→ 全新克隆的宿主机上**没有这个目录**。若用 bind mount（`- ./storage:/app/storage`
或 `-v /opt/ai4s/storage:/app/storage`），compose / docker 会在宿主机新建一个
**root:root 755** 的空目录挂进容器，而容器内进程是 uid 10001（Dockerfile `USER app`）。
结果是 `config.py:42` 的 `mkdir` 抛 `PermissionError`（发生在 import 期），
`config.py:42` 的 mkdir 抛 `PermissionError`，发生在 import 期。
（页面文案现在**已经准确**：`app.py:43` 用 `isinstance(e, OSError)` 分流，
显示「storage/ 目录不可写（容器挂载属主不对）」，`:45` 还会给出 chown 命令。
但**报错准 ≠ 能用** —— 评委看到这句话时应用是起不来的，所以下面这步 chown 仍是必做。）

**bind mount 前必须执行**：

```bash
mkdir -p storage && sudo chown -R 10001:10001 storage
```

### 9.4 变更：`docker-compose.yml` 改为命名卷 `app_storage`

为了避免上面这个「全新克隆一起就崩」的坑，`docker-compose.yml` 已把
`- ./storage:/app/storage` 改为命名卷 `- app_storage:/app/storage`。
Docker 在创建新命名卷时会把镜像内 `/app/storage` 的内容**连同属主**复制进卷，
而 Dockerfile 第 4 层已把该目录及子目录预置并 chown 给 `app:app`。
（属主是否随 copy-up 保留**本机无 docker，未实测** —— 首次 up 后请按
`docs/部署后自检清单.md §1.1` 跑一次 `ls -ld` 校验。）

影响 §2.5 的备份说法：`tar czf backup.tgz storage/` **不再适用**（宿主机上没有这个目录了）。
改用：

```bash
# 备份
docker compose cp ai4s-agent:/app/storage ./storage_backup
tar czf backup.tgz storage_backup

# 查看（不进容器）
docker run --rm -v <项目名>_app_storage:/s alpine ls -l /s
```

想改回 bind mount 的三步操作写在 `docker-compose.yml` 的 volumes 注释里。
