> 来源：`https://element.eleme.cn/#/zh-CN` 的主题样式表的实测抽取
> （`https://unpkg.com/element-ui@2.15.14/lib/theme-chalk/index.css`，240 033 字节），
> 对照本仓库 `ui/design.py` 现状，转化为可执行的版式规则。
> 为什么用 CSS 而不用截图：颜色/字号/圆角这类"感觉"只有落到具体数值才能被门禁看守，
> 抽出来的每个数都带出现频次，能分辨"体系"和"随手写的值"。

**结论一（重要）**：令牌层我们已经不比 Element 差——中性灰阶更纯、间距严格 8 倍数
（Element 存在 22px 表单项间距、20px 卡片内边距这类非 8 倍数），圆角更统一。
所以"乱"不在色板/字号，而在**每一块内容有没有归属容器、有没有固定的信息层级**。

## 二、Element 真正值得学的 7 条版式规则

1. **一切内容都有容器**：Element 页面里没有"裸"元素浮在底色上，要么 Card、要么
   Collapse、要么 Table。我们的对应物是 `st.container(border=True)`——
   但 14 处用法**没有统一外观**（1.63 已无 `stVerticalBlockBorderWrapper` testid，
   实测 DOM 里找不到该标识），所以卡片边界只靠 Streamlit 默认，视觉上时有时无。
2. **一个容器只有一个标题 + 一组主操作**：Card header 承载标题与按钮，body 只放内容。
   我们目前的形状是「section_header + 若干控件 + 若干 caption」平铺，操作按钮与说明
   混排，看不出"这一段该干什么"。
3. **层级只用三样东西**：灰阶文字、1px 边框、留白。不用阴影、不用第二色相。
   （我们已满足，继续守住。）
4. **密度恒定**：控件高度两档（32 / 40），表单项行高固定 22px，label 与控件基线对齐。
   我们 `--ctl-h:36px` 单档，已经恒定；风险在**表格/卡片内手工 padding**。
5. **分组靠折叠，不靠平铺**：Collapse 默认收起。我们已有"首屏减法"（其余收进
   expander），42 处 expander 是执行到位的表现——但要复查`默认展开`的数量。
6. **状态四态齐备**：默认 / hover / active / disabled 都有明确底色差。
   Element 用 `#ECF5FF`（主色 10% 级）做 hover。我们的 `--c-accent-soft` 是 8%，
   在正文区几乎不可见——**唯一需要改的令牌用法**（见三-3）。
7. **空态与结果态必须显式**：Element 的 Empty 组件是标准件。我们有
   `empty_state_card`，但要保证「算不出来」与「没算过」在视觉上不同。

## 四、纪律

- 令牌只在 `ui/design.py` 定义；页面里不写死颜色/字号/间距（`_verify_theme.py` 静态扫描）。
- 任何"美化"都必须先有**可量的口径**（元素数、控件数、色块数、计算样式），
  不接受"看起来顺眼了"这种结论。
- 改选择器前先在真实 DOM 里确认标识存在：1.63 的 `stVerticalBlockBorderWrapper`
  已经不存在，照旧文档写选择器等于写了条永不生效的规则。
