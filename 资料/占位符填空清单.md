## 五、填写模板（格式规范）

1. **学校 / 学院**：`XX大学·计算机科学与技术学院`——用全称、不用缩写；校名与院系之间用 `·` 分隔。
2. **姓名 / 年级 / 专业**：姓名写真实姓名；年级写"入学年份 + 级"（如 `2023 级`）；专业写全称。
3. **指导老师**：`姓名 + 职称 + 单位`，职称从 教授 / 副教授 / 讲师 / 高级工程师 中选；
   **无指导老师时，README:364 与团队信息.md:18、:57 三处都明确写"无指导教师"**，不要留空。
4. **联系方式**：手机 11 位数字；邮箱用 `name@domain` 常规格式，域名须真实可收信
   （赛方可能邮件回访），**正式材料里不要用 `example.com`**——它只是本清单的格式示范保留域。
5. **参赛组别 / 赛道 / 队伍名称**：组别仅限 本科组 / 研究生组 / 高职组；
   队伍名称、组别、赛道名称与报名表单**一字不差**（团队信息.md:83 自查条第 3 条同义）。

## 七、分工矩阵怎么填

### 两张表的列含义

- README:354 `| # | 姓名 | 学校 / 专业 | 组别 | 负责模块 | 主要交付物 |`
- 团队信息.md:30 `| # | 姓名 | 学校 / 专业 / 年级 | 组别 | 负责模块 | 主要交付物 |`

| 列 | 填什么 |
|---|---|
| `#` | 行号 1–7，对应七大模块；合并 / 拆分行后顺延重排 |
| `姓名` | 真实姓名；第 1 行（队长）姓名后加"（队长）" |
| `学校 / 专业`（README） | 每人一行独立填，如 `XX大学·计算机科学与技术学院` |
| `学校 / 专业 / 年级`（团队信息.md） | 三段都填，如 `XX大学 / 计算机科学与技术 / 2023 级` |
| `组别` | 与报名表单一致（通常全队同一组别） |
| `负责模块` / `主要交付物` | **已按七大模块预填，默认不用改**；仅当合并 / 拆行时调整 |

### 人数少于 7 人：怎么合并行

团队信息.md:28 原文提示："若实际人数多于 / 少于 7 人，请合并或拆分相应行"；
README:368 另有约束："保持每个模块有且仅有**一名主要负责人**"。操作步骤：

1. 把相关模块并入同一行，`负责模块` 列写多个模块名，用 `+` 连接；
2. 一行多人共担时，`姓名` 列用 `、` 分隔，**主要负责人放第一位**；
3. 合并后行数变少，`#` 列重新编号；同步把团队信息.md:44–49 代码定位对照表的
   `[成员 N]` 改成对应姓名；
4. 多于 7 人：把某个模块拆成多行，同样保持"一个模块一名主要负责人"。

`[示例]` 3 人团队的合并写法（仅示范格式，非真实信息）：

| # | 姓名 | 学校 / 专业 / 年级 | 组别 | 负责模块 | 主要交付物 |
|---|---|---|---|---|---|
| 1 | `[示例] 张三`（队长） | `[示例] XX大学 / 计算机科学与技术 / 2023 级` | `[示例] 本科组` | Agent 内核 + 总体架构 | `core/`（agent / planner / router / memory / guardrails / sandbox / trace） |
| 2 | `[示例] 李四` | `[示例] XX大学 / 计算机科学与技术 / 2023 级` | `[示例] 本科组` | 多模态文档感知 + 抗幻觉 RAG | `services/parsing.py`、`services/library.py`、`services/rag.py` |
| 3 | `[示例] 王五` | `[示例] XX大学 / 软件工程 / 2022 级` | `[示例] 本科组` | 引用图谱 + 学术 Copilot + UI + 测试交付 | `services/graph.py`、`services/writing.py`、`ui/`、`tests/` |
